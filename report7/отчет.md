# Grafana дашборд Repair Desk

## Что сделано

Grafana развёрнута в namespace `monitoring`. В datasource `VictoriaMetrics` используется Prometheus-совместимый API VictoriaMetrics single:
`http://vm-single-victoria-metrics-single-server:8428`.

Основной дашборд `Repair Desk — обзор и SLA` экспортирован в `k8s/monitoring/grafana/application.json`. Он автоматически загружается provisioning-конфигурацией.

## Панели приложения

- доступные API targets и последний результат синтетического пробера;
- RPS с группировкой по HTTP-статусу;
- доля ответов 5xx;
- p95 задержки API;
- доля запросов, завершившихся не позднее 250 мс;
- длительность сценария пробера;
- CPU процесса API;
- RSS процесса API;
- число горутин Go;
- выделенная heap-память и средняя пауза GC.

Панели выбраны по RED/USE/Golden Signals: rate и errors описывают трафик и ошибки, latency — задержку, а CPU, RSS, heap и goroutines показывают использование ресурсов и состояние рантайма.

## SLA пробера

Отдельная stat-панель считает долю хороших минут по методике ДЗ5:

```promql
min(avg_over_time(min_over_time(repairdesk_probe_success[1m])[30d:1m]))
```

Пороговые линии панели: SLA 99% и SLO 99.5%. Отдельная панель показывает покрытие окна данными. Это важно: если истории за 30 дней ещё нет, нельзя выдавать короткую историю за доказательство месячной доступности.

## PostgreSQL Exporter

Импортирован дашборд `Postgres Overview` из репозитория postgres_exporter и сохранён как `k8s/monitoring/grafana/postgres.json`. Он использует тот же datasource VictoriaMetrics и показывает `pg_up`, подключения, транзакции, чтение/запись, cache hit ratio, locks и deadlocks.

## Запуск

```sh
kubectl apply -k k8s/monitoring/grafana
kubectl -n monitoring rollout status deployment/grafana
kubectl -n monitoring port-forward svc/grafana 3000:80
```

Логин `admin`; пароль задаётся Secret `grafana-admin`. В учебном стенде пароль можно получить из Secret или задать при создании. После открытия Grafana доступны дашборды:

- `Repair Desk — обзор и SLA`;
- `Postgres Overview`.

## Проверка

Проверить JSON можно так:

```sh
python -m json.tool k8s/monitoring/grafana/application.json >/dev/null
python -m json.tool k8s/monitoring/grafana/postgres.json >/dev/null
kubectl kustomize k8s/monitoring/grafana
```

На Kubernetes VictoriaMetrics должен иметь таргеты API, prober и `postgres-exporter`; тогда панели заполняются временными рядами. Если `pg_up` отсутствует, сначала проверяется scrape target exporter, а затем его `DATA_SOURCE_NAME`.
